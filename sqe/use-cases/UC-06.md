# UC-06 — Cancel an order using only the keyboard

| Field | Value |
|---|---|
| Workflow | W2 Cancel an order |
| Author | Member 3 |
| Primary actor | Orders Manager who operates the control panel with the keyboard only (no mouse) |
| Goal | Cancel an order, optionally keeping a fee, with every control reachable and operable by keyboard and with errors that explain how to correct them |
| Trigger | A customer asks the organiser to cancel |
| Requirements | CAN-01, CAN-02, CAN-03 |
| Business rules | BR-02 cancellation admission, BR-03 fee limit (0 ≤ fee ≤ order total), BR-04 cancellation outcome |
| Risks | R5 excess fee / wrong total, R7 wrong ticket eligibility, R15 negative fee accepted, R17 keyboard users blocked |
| Automation | `src/tests/team/e2e/uc05-uc06.spec.js` (tests titled `UC-06 …`); main flow and E1 also serve as usability test USA-02 |

## Preconditions
1. The SQE instance is reset and the manager is logged in.
2. The order has one active EUR 20.00 position and the state named in each flow.
3. Only Tab, Shift+Tab, Space and Enter are used once the order page is open.

## Main flow — paid order, no fee (`m3_kbd_paid`)
1. Manager tabs to **Cancel order** on the order detail page and presses Enter.
2. System shows the *Cancel order* form.
3. Manager tabs through the form. Focus order must be: **Keep a cancellation fee of → Notify customer by email → Comment → No, take me back → Yes, cancel order**.
4. Manager moves focus to *Notify customer by email* and presses Space to untick it.
5. Manager tabs to **Yes, cancel order** and presses Enter.
6. System confirms "The order has been canceled." (with a refund prompt for a paid order).

## Alternative flows
- **A1 — Zero fee on a pending order (`m3_zero_fee`)**. At step 3 the manager types `0.00` in the fee field and presses Enter. A zero fee is treated as "no fee": the order is canceled.
- **A2 — Abandon (`m3_abandon`)**. At step 3 the manager tabs to **No, take me back** and presses Enter. The system returns to the order detail; nothing changes.

## Exception flows
- **E1 — Fee above the order total, then corrected (`m3_fee_fix`)**. At step 3 the manager types `20.01` and presses Enter. The system shows the form again with the message "The cancellation fee cannot be higher than the total amount of this order." next to the fee field, keeps the typed value, and changes nothing. The manager corrects the value to `19.99` and presses Enter; the system cancels the positions, keeps a 19.99 fee and leaves the order Paid (20.00 paid ≥ 19.99).
- **E2 — Negative fee (`m3_neg_fee`)**. At step 3 the manager types `-0.01` (just below the lower limit 0) and presses Enter. Expected by BR-03: the form shows an error and nothing changes. *Observed:* the cancellation succeeds — every position is canceled, a cancellation fee of **−0.01** is stored, the order total becomes **−0.01** and the status stays paid — **known defect D-01** (no minimum on `CancelForm.cancellation_fee` or the API `cancellation_fee`). Automated as a `test.fail()` known-defect test that attaches the stored order.

## Postconditions (API readback before and after)
| Flow | Status | Total | Positions | Cancellation fees | Payments |
|---|---|---|---|---|---|
| Main | `c`, cancellation date set | 20.00 | rows kept | 0 | confirmed 20.00 kept |
| A1 | `c`, cancellation date set | 20.00 | rows kept | 0 | none |
| A2 | unchanged `p` | 20.00 | unchanged | 0 | unchanged |
| E1 after rejection | unchanged `p` | 20.00 | unchanged | 0 | unchanged |
| E1 after correction | `p` | 19.99 | all canceled | 1 × 19.99 | confirmed 20.00 kept |
| E2 (expected) | unchanged `p` | 20.00 | unchanged | 0 | unchanged |
| E2 (observed, D-01) | `p` | −0.01 | all canceled | 1 × −0.01 | confirmed 20.00 kept |

## Test design techniques
- Boundary value analysis on the fee: −0.01 (below 0), 0.00 (at 0), 19.99 (below cap), 20.01 (above cap). 20.00 (at cap) is covered by UC-03.
- Equivalence partitions: empty (UC-02) vs zero (A1) vs positive within cap (E1) vs above cap (E1) vs negative (E2).
- State transitions: `p → c`, `n → c`, `p → p` with retained fee, `p → p` unchanged after rejection.
- Usability: focus order, keyboard operability, error message that names what to correct.
