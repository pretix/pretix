1. Use the verified REST contracts and decision and state tables. Write or validate the OpenAPI spec for order detail and the two POST actions. Enumerate path and body fields, authentication, content types, response classes, defaults, optional fields and nullability. Confirm the implemented behavior of `send_email`, `comment`, and `cancellation_fee`. Model the dynamic fee cap with a documented extension or fixture parameter. The payment action derives the amount from the outstanding balance. [Pinned REST implementation](../../src/pretix/api/views/order.py)
2. Write a deterministic generator that reads the spec and emits IDs, valid and invalid equivalence partitions, boundary triples, a base request with one field override, and expected classifications with reasons. Use `Decimal` and EUR increments of `0.01`. For every input, track valid and invalid partitions and the three values around applicable bounds. Record why a specific input has no orderable bound. Cover slug and order code format, resource existence, types, booleans, omitted, null and empty values, precision and length where applicable. Change two constraints in a separate spec revision and preserve both datasets and their differences.
3. Parameterize pytest and Requests from the generator output. Supply the synthetic role tokens from a private location. Record which app instance the runner uses. Point the test client at http://127.0.0.1:18081 for the shared Windows fixture app. Check operations, parameter locations, roles, response classes, decisions, state transitions and repeats, and document coverage gaps. Use one invalid input per negative partition test and count each executable case once per level.
4. Check business and database or API postconditions after success and rejection. Verify confirmed payments, active positions, fees, totals and duplicate counts. Distinguish audit or failed-attempt records from the business writes under test. Demonstrate W1 → W2 on the same order. Record endpoint weaknesses with evidence, root cause, severity, risk and proposed correction. Update the handoff for Phase 5.
