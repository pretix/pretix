Tawassul owns mutation and CI. Start the PR workflow and check runner access to SonarQube while the team develops the suites. **Evidence.** Mutation reports, at least two implemented custom operators, and real PR evidence. Every PR runs the required checks. Demonstrate one blocked PR and one documented fix with fail → pass evidence.

1. Run mutmut or Cosmic Ray in a separate Linux test container launched from PowerShell. Check compatibility with the pinned Django and test environment. Target the declared business-rule modules and isolate generated mutants. Record the initial score and survivor list. Implement at least two custom operators based on the rules, such as removing the active-position condition and changing the fee-cap comparison.
2. Analyze at least 15 distinct surviving mutants from real runs. Classify each as equivalent, missing test or weak assertion, and kill the killable ones. Report before-and-after scores with denominators, timeouts and treatment of equivalent mutants. If the initial run yields too few survivors, broaden within the agreed rule scope or use recorded runs from earlier suite versions. Record any remaining shortfall as pending.
3. Configure GitHub Actions in the team fork for every PR. Provision the test database and build from the candidate source for each run. Run Tawassul's unit tests, Member 2's API suite, Member 3's recovery test, and the integrated Chromium suite. Run coverage, mutation and SonarQube. Run the automated accessibility and other checks with their documented CI prerequisites. Record the runner OS and its fixture and reset configuration. Verify SonarQube reachability and authentication, and document the scan strategy supported by the chosen setup. Retain reports and keep the controlled Windows k6 measurements identifiable in the evidence.
4. Justify the coverage, mutation and SonarQube thresholds. Require the checks on the fork's planned integration branch, `master`. Verify the full set of required checks before merging the teammate PRs. Gate release packaging and deployment on passing results and let check failures propagate. Link an actually blocked PR and a documented fix PR with failing and passing runs and a regression assertion. Give Phase 9 the PR links, workflow run IDs and tested commit SHAs.
